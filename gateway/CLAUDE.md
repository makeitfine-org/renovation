# :gateway

API gateway on **Spring Cloud Function** (web starter) + Spring Boot 3.2.0 — **not** Spring Cloud Gateway. OAuth2 client for Keycloak; also supports GitHub & Google social login.

## Role

- Handles browser login via OAuth2 authorization-code flow against Keycloak.
- Forwards authenticated requests to `:backend` and `:info`.
- No data layer — stateless apart from session.

## Tests

| Command | Notes |
|---|---|
| `./gradlew :gateway:test` | unit |
| `./gradlew :gateway:integrationTest` | needs Testcontainers Keycloak 18.0.2 |
| `./gradlew :gateway:e2eTest` | needs the full Docker Compose stack — see `/stack-up` |

### Parallel-forks caveat

`maxParallelForks` is commented out in the root `build.gradle.kts` (~line 143) so gateway ITs run **sequentially**. Tests in this module are sensitive to shared Keycloak state — do **not** re-enable parallel forks without coordinating across the three affected ITs (`SocialLoginTest`, `ExposeApiConfigIntegrationTest`, and siblings).

## OAuth2 config

- `application.yml` defines the Keycloak, GitHub, and Google providers.
- Keycloak realm fixture for tests: `src/test/resources/keycloak/renovation-realm-test.json` is gitignored (see root `.gitignore`) — regenerated by the test init step.

## Local run

```bash
./gradlew :gateway:bootRun      # host 8085 in-process, 8285 via docker compose
```

## Do not

- Migrate this away from Spring Cloud Function without a project-level discussion — routing, `functions.yaml`, and OAuth2 config would all change.
- Hardcode downstream URLs — use the existing `routes` / `expose` config.
